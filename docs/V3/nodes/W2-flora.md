# W2 生态位场与植被：设计

状态：设计（2026-11-19，主会话；W1 接线期间写好，W1 打标签后开工）。验收条件在 `docs/V3/STATUS.md` 的 W2 一节。现有植被渲染的梳理在 `docs/V3/maps/world-view-streaming.md` 3.7 与 S5–S7。

## 要回答的问题

“这里长什么”在整个游戏里只回答一次，在纯核心里回答：渲染层照它画树、灌木、地被和草；采集（W3）从它派生；以后动物的栖息与掩体、鱼的岸边栖息地、弹道与视线也读它。答案是世界种子和位置的纯函数，和谁先问无关。

## 现在的做法（第 1 版世界保持不动）

树、灌木、石头、仙人掌只存在于渲染层：128 m 的瓦片、8 m 的格子，位置来自 `hash2(格x, 格z, 种子 + 0x7ee5)`，种类由 `worldBuild.ts` 里一串按群系 id 写死的判断决定，用到渲染层的 `woodland()`（林冠）和两张林丛噪声。树没有碰撞，核心不知道哪里有树。第 1 版世界继续走这条老路，画面不变；下面全部只对第 2 版世界生效。

## 三层结构

### 1. 生态位瓦片 `src/core/world/ecotope.ts`

128 m 见方、8 m 网格（17 × 17 个结点，外加一圈用来求导的边），和渲染层的植被瓦片对齐。一个瓦片算一次、放进有上限的缓存；所有使用者都从瓦片取值，不各自去问地形函数（地形函数每次约 1 微秒，一个瓦片 361 次约 0.4 毫秒）。

每个结点的量：

| 量 | 含义 | 怎么来 |
| --- | --- | --- |
| `h`、`ad`、`zone`、区域混合 | 高度、离路距离、路面/路肩/场地/地块、所在区域 | 地形函数 |
| `slope` | 坡度（升距比） | 网格差分 |
| `shade` | 0 向阳 … 1 背阴 | 坡向对太阳方位 |
| `hollow` | −1 凸起 … 1 洼地 | 网格拉普拉斯 |
| `waterDist`、`waterKind` | 到最近水边的距离（上限 150 m）与水体种类 | 水体规划的解析距离（给 `WaterPlan`、`SeaPlan` 各加一个只读的岸距函数） |
| `canopy` | 0 开阔 … 1 密林 | 参数化的林冠函数：区域给出覆盖率、斑块尺度、林线、离路留白、近水偏好 |
| `moisture` | 0 干 … 1 湿 | 区域基准 + 近水 + 洼地 + 背阴 − 陡坡 + 一张慢噪声 |

### 2. 植被场 `src/core/world/flora.ts`

分层，每层一张格子、各用各的哈希盐：

- 乔木层与灌木层：8 m 格，一格至多一株。
- 地被层：4 m 格，稀疏（草本丛、花丛、朽木、石块，以及 W3 的地面采集物）；只在玩家附近实例化。
- 草与花毯：不是一株一株的，是密度场 `groundCover`：草的密度与高度、花的密度与花色、成垄的周期（花海的垄、梯田平台上的作物）、裸地比例、林下落叶。给草的渲染用。

一格的决定：哈希给出格内位置和几个骰子 → 排除路的走廊、水里、场地、地块 → 按区域混合比挑一个区域的植物表 → 逐条规则算“适合度 × 每公顷株数”，按累计概率落在哪条规则上就是哪种植物，都没落上就是空地。

规则是一行数据：`{ plant, perHa, niche: 各量的区间, size, grove?: 成片的尺度 }`。乔木主要跟着林冠走；灌木偏爱林缘；芦苇只在水边几米；作物只在梯田的平台上；花海按垄。

### 3. 植物目录与区域植物表 `src/core/world/plants.ts`、`src/core/world/regions/*.ts`

`PlantDef`：id、层、名字、株高范围、冠幅、树干半径、常绿与否、渲染用的模型族、以及它结什么（`bears`：采集物 id，结在树上还是落在树下）。果树、坚果树、浆果丛在这里就定下来，所以 W3 不用再回答“苹果长在哪”：有苹果树的格子就有苹果。

第一批 12 种区域各一张植物表（6–12 行）。第一批需要的新植物：竹、柳、茶丛、芦苇与香蒲、稻与作物垄、花垄（薰衣草、油菜花、向日葵）、果树与坚果树（苹果、柿、樱桃、栗、核桃；树冠里看得见果子）、浆果丛、鼠尾草丛、龙舌兰、仙人掌梨、朽木、蕨丛。能用现有模板加配色和比例做的不新建模型。

## 树有没有碰撞

核心提供 `floraSolidsNear(x, z, r, out)`（树干是圆柱）。第 2 版世界里接给步行者和车辆；条件是机器人驾驶、路边残骸与地点的现有测试全部通过（树不长在路的走廊、场地和地块上，残骸不会生成在树里）。有问题就先只接步行者，车辆留到狩猎节点。

## 分工

1. 主会话：`ecotope.ts`、`flora.ts`、`plants.ts` 的第一版，以及植物表的结构与前两种区域的样板行。
2. 一位工程师：把核心做扎实（确定性、缓存、各区域的植被统计、耗时），补齐 12 种区域的植物表，给水体加岸距函数。
3. 一位工程师（渲染）：第 2 版的植被瓦片改为读核心；植物注册表与细节分级；新植物的模型；草与花毯读 `groundCover`；远景林带与地面着色器里的树冠色块改用新的林冠；自检截图。

## 验收补充（STATUS 里的条目之外）

- 每种区域：林地占比、林内与林外每公顷株数、种类数在设计区间内（数字写进测试）；林线、水边、梯田平台、花垄各有专门的断言。
- 每种“长在树上或树下”的采集物至少在一种区域有宿主植物。
- 一个瓦片的生态位约 0.5 毫秒、植被格约 0.1 毫秒（Node 实测并写明）；缓存有上限，换出再算结果相同。

## 怎么加一种植物、给一种区域加一行

1. `plants.ts` 末尾加一行 `PlantDef`（模型族用现有的，或在渲染层的植物注册表里登记一个新的）。
2. 在该区域文件的 `flora` 表里加一行规则：每公顷株数、喜欢的生态位区间、大小。
3. 跑 `npx vitest run harness/sim/v3_flora*.test.ts`：统计区间、排除规则、确定性都要过；用测试面板传送到该区域看一眼。
