# W2 生态位场与植被：设计

状态：核心已做完（2026-11-18：`world.eco`、`world.flora`、岸距、瓦片缓存、树干碰撞体、十二种区域的统计与专项断言、确定性）；渲染接线进行中。验收条件在 `docs/V3/STATUS.md` 的 W2 一节。现有植被渲染的梳理在 `docs/V3/maps/world-view-streaming.md` 3.7 与 S5–S7。

## 要回答的问题

“这里长什么”在整个游戏里只回答一次，在纯核心里回答：渲染层照它画树、灌木、地被和草；采集（W3）从它派生；以后动物的栖息与掩体、鱼的岸边栖息地、弹道与视线也读它。答案是世界种子和位置的纯函数，和谁先问无关。

## 现在的做法（第 1 版世界保持不动）

树、灌木、石头、仙人掌只存在于渲染层：128 m 的瓦片、8 m 的格子，位置来自 `hash2(格x, 格z, 种子 + 0x7ee5)`，种类由 `worldBuild.ts` 里一串按群系 id 写死的判断决定，用到渲染层的 `woodland()`（林冠）和两张林丛噪声。树没有碰撞，核心不知道哪里有树。第 1 版世界继续走这条老路，画面不变；下面全部只对第 2 版世界生效。

## 入口

`world.eco`（`EcotopeField`）和 `world.flora`（`FloraField`）是 `World` 的惰性成员：第 2 版世界第一次访问时才创建，创建时什么都不算；第 1 版世界是 `null`。各区域的植物表通过 `floraTableOf(BIOMES[r].id, BIOMES[r].kin)` 取。

加载顺序：`terrain.ts` 运行时导入 `ecotope.ts`、`flora.ts`、`floraTables.ts`；这几个文件对 `terrain.ts` 只做类型导入（和 `sites.ts`、`furniture.ts` 一样，由 `World` 把一个 `TerrainPoint` 交给它们用），所以没有环。`harness/sim/v3_flora.test.ts` 里有一条断言沿导入关系检查这一点。

## 三层结构

### 1. 生态位瓦片 `src/core/world/ecotope.ts`

128 m 见方、8 m 网格（17 × 17 个结点，外加一圈用来求导的边），和渲染层的植被瓦片对齐。一个瓦片算一次（约 0.4 毫秒）、放进有上限的缓存（`capacity`，缺省 320，可调大）；所有使用者都从瓦片取值，不各自去问地形函数。

每个结点的量：

| 量 | 含义 | 怎么来 |
| --- | --- | --- |
| `h`、`ad`、`flags`、`ra/rb/rt` | 高度、离路距离、路/水/场地/地块、所在区域与混合比 | 地形函数 |
| `slope` | 坡度（升距比，跨 16 m 差分） | 网格差分 |
| `shade` | 0 向阳 … 1 背阴 | 坡向对太阳方位 |
| `hollow` | −1 凸起 … 1 洼地 | 网格拉普拉斯 |
| `waterDist`、`waterKind` | 到最近水边的距离（上限 150 m，水里是 0）与水体种类（1 湖 2 河 3 海） | 水体自己给的岸距，见下 |
| `canopy` | 0 开阔 … 1 密林 | 区域给出覆盖率（0 就是没有林子）、斑块尺度、林线、离路留白、近水偏好；坡度 0.8 以上变稀，1.4 以上没有；沿海公路朝海一侧保持开阔（`sea.open`） |
| `moisture` | 0 干 … 1 湿 | 区域基准 + 近水 + 洼地 + 背阴 − 陡坡 + 一张慢噪声 |
| `relief` | 高出路基多少（不含锚定地貌） | 地形函数 |
| `landform` | 锚定地貌（峰林、桌山）在这里的高度，没有就是 0 | `TerrainPoint.landform` |
| `terrace`、`step` | 这一段是不是梯田（0 … 1）、每级多高 | `world.land.at` |
| `open`（按 8 m 方格） | 这一格周围 16 个结点都不是路、水、场地、地块，且四角离水不小于 8 m | 上面几项 |

**岸距**（`WaterPlan.shore`、`SeaPlan.shore`，由 `shoreOf(world)` 合成后交给生态位场）：只用水体规划自己的几何，不问地形，所以相邻瓦片在公共边上取到同一个数。

- 湖：把 `lakeRho` 的岸线沿 256 条射线描一遍（每个湖一次），距离就是到这条折线的真实距离。
- 海：岸线是 x 的函数（同 x 的路点 + `shoreAt`），每 4 m 描一个点（每片海一次），距离同样是到折线的真实距离。
- 河：用 `carve` 切河道的同一个量（同 z 处到中线的垂距减去半宽）；近岸等于真实距离，150 m 处在急弯内侧可能差八分之一；河道在尽头淡出的那一段，距离逐渐加大直到不再算作有河。

和地形函数自己的“这里有没有水”逐米比对过：有水的地方岸距是 0，岸外第一米不到 1 m，没有台阶（湖和海沿任何直线每走一米变化不超过一米）；和在网格上穷举出来的“到最近的水”相比，湖和海在 150 m 以内处处相差不到网格的 2 m。

### 2. 植被场 `src/core/world/flora.ts`

分层，每层一张格子、各用各的哈希盐：

- 乔木层与灌木层：8 m 格，一格至多一株（所以每公顷至多 156 株；表里写得比这大，意思是“合适的格子每格一株”，芦苇就是这样写的）。
- 地被层：4 m 格，稀疏（草本丛、花丛、朽木、石块，以及 W3 的地面采集物）；只在玩家附近实例化。
- 草与花毯：不是一株一株的，是密度场 `flora.cover(x, z, out, y?)`：草的密度与高度、花的密度与花色、成垄的周期、裸地比例、林下落叶。传入地面的真实高度 `y` 时，梯田上的垄只长在平台上。

**按瓦片取**：`flora.tile(layer, tx, tz)` 返回这一层在这块 128 m 瓦片里的全部植物，打包成数组（`plant`、`x`、`z`、`y`、`size`、`yaw`、`vary`、`rule`、`region`，另有 `row` 标出每一行格子的起点），算一次、放进有上限的缓存（`capacity`，缺省 768，三层合计）。渲染、采集、碰撞都读同一份。`flora.cell(layer, cx, cz, out)` 是同一个决定，单格问。

一格的决定：

1. 哈希给出格内位置和骰子；骰子先和“这张表最多能凑到多少”比，大多数地被格到这里就结束了。
2. 地面：落在 `open` 方格里的，直接当作干地；否则问一次地形，场地、地块、深水里的格子结束，浅水（不超过 0.7 m）里只有水生植物参与，干地上只有陆生植物参与。
3. 逐条规则算“适合度 × 每公顷株数”，按累计概率落在哪条规则上就是哪种植物，都没落上就是空地。成片的规则（`grove`）再乘一张噪声。
4. 站得住的植物，高度取地形函数在该点的真实高度（生态位网格插值出来的高度会差十几厘米到一米，沙丘和峡谷壁上更多，不能用），所以每株植物仍然问一次地形。

规则是一行数据：`{ plant, perHa, 各量的区间, size, grove? }`，另有两个字段：`landform`（长在锚定地貌上，或不长在上面；边缘固定 3 m 宽）、`bench: true`（只长在梯田的平台上：所在路段是梯田，并且植物脚下的真实高度正好是台阶高度的整数倍）。

### 3. 植物目录与区域植物表 `plants.ts`、`floraTables.ts`、`floraForage.ts`

`PlantDef`：id、层、名字、株高范围、冠幅、树干半径、常绿与否、渲染用的模型族、以及它结什么（`bears`）。区域植物表以区域 id 为键放在 `floraTables.ts`；地面采集物长在哪种小环境、哪些区域，在 `floraForage.ts` 里一行一种，生成时并进各区域的地被规则。

## 树的碰撞 `src/core/world/floraSolids.ts`

`FloraSolids`（一个 `SolidSource`）和 `floraSolidsNear(flora, x, z, r, out)`：乔木层的每棵树是一根圆柱，半径是 `PlantDef.trunk × size`，从根下 0.6 m 到树顶。取自乔木瓦片，每块瓦片的圆柱只建一次，同一棵树每次返回同一个对象。

还没有接给步行者和车辆。要接：在组装玩家碰撞源的地方（`src/game/scene/siteThings.ts`，`player.solids.add(world.sites)` 旁边）对第 2 版世界加一行 `player.solids.add(new FloraSolids(world.flora))`。条件是步行、驾驶、地点与路边设施的现有测试全部通过。已知问题：树不长在场地的平整地面上，但少数地点有东西摆在平整地面之外（码头、灯塔），抽查约两千件里有三件和树干重叠，接线时要先处理。

## 验收（测试都在 `harness/sim/v3_flora*.test.ts`）

- `v3_flora_regions`：十二种区域各作为出发地、以及在旅途中被发到时，林地占比、林内与林外每公顷株数、乔木与灌木种类数、每公顷可采株数与种类数都在区间内。
- `v3_flora_country`：林线、芦苇与柳树只在淡水边、水生植物只在浅水里、茶在平地和梯田平台上、花垄只在平地上、竹子成片、峰林的陡坡上不长东西、路的走廊、深水、场地、地块上什么都不长。
- `v3_flora_shore`：岸距对照地形函数。`v3_flora_tiles`：瓦片等于逐格、缓存有上限、决定与不走任何捷径的写法逐位相同。`v3_flora_determinism`：换顺序、换出再算、跨区域边界、同种子两个世界。`v3_flora_solids`：树干。
- 耗时（Node 实测）：生态位瓦片约 0.4 毫秒；一块森林瓦片的三层植物 0.72 毫秒（改之前 2.50），草地瓦片 0.51 毫秒（改之前 2.41）。

## 怎么加一种植物、给一种区域加一行

1. `plants.ts` 末尾加一行 `PlantDef`（模型族用现有的，或在渲染层的植物注册表里登记一个新的）。
2. 在 `floraTables.ts` 该区域的表里加一行规则：每公顷株数、喜欢的生态位区间、大小。地面采集物改 `floraForage.ts` 里它那一行的区域列表。
3. 跑 `npx vitest run harness/sim/v3_flora`：统计区间、专项断言、确定性都要过（改了数量就按新结果调整 `v3_flora_regions` 里的区间）；用测试面板传送到该区域看一眼。
