# W1 世界生成核心：设计

状态：设计（2026-11-19，主会话）。验收条件在 `docs/V3/STATUS.md` 的 W1 一节。现有生成器的梳理在 `docs/V3/maps/world-core.md`（行号对应提交 `e50503c`，以源码为准）。

## 现在的世界是怎么生成的（一句话版）

先生成一条路（`RoadSpine`，每 2 m 一个点，x 单调递增），再把地“挂”在路上：`World.shape(x, z)` 用“同 x 的路点”和“最近的路点”算高度。沿路每 1,250 m 一个路段（slot），按顺序、只看后面地决定地貌截面（开阔、山坡、谷、脊、峡谷）、水（湖、河）、海岸、地点。群系按“章”（10–18 km）发牌，6 种。全部是种子的纯函数。

## 目标

1. 第 1 版世界逐位不变（老存档）。有测试看着。
2. 第 2 版世界：区域是数据，可以一直往表里加；旅途有节奏（舒缓为主，张弛有度）；有新的地貌。
3. 给后面的层（生态位、植被、采集、钓鱼、狩猎）一个稳定的问法：这里是什么区域、什么地貌、离水多远。

## 分四步，每步都是能运行的提交

### W1.0 金样、版本、区域注册表（第 1 版逐位不变）

- **金样**：`harness/sim/worldTrace.ts` 按 `world-core.md` 附录 A 的定义给世界留指纹（路线、章、地貌、水、海、地点、地标、路边设施、两万个高度采样），四个参考世界的指纹写进 `harness/sim/world-golden.json`，`harness/sim/world_golden.test.ts` 逐项比对；每个世界再用另一种查询顺序建一次，指纹必须相同。附录 A 的数值是在 `e50503c` 上记录的，先原样复现，再做下面的改动。
- **版本与规则**：`WorldOptions.worldVersion?: 1 | 2`（缺省 1）；`src/core/world/rules.ts` 把第 1 版散在各处的常数（章长、发牌池大小 3 和 6、安静段“九段里两段”、路段长度 1,250 等）集中成 `RULES_V1`，第 2 版是另一份规则对象。各个 plan 从规则对象读，不再各自写死。
- **区域注册表**：`BIOMES` 仍是唯一的数组，只追加，下标就是身份（下标参与噪声种子）。`RegionDef extends BiomeDef`，新增可选字段（见下）。第 1 版发牌池大小写死为 6，这样追加区域不会改变任何老世界。所有“按群系 id 查表、查不到用草原”的地方改成“区域自己带的 → 按 id 查表 → 按 `kin` 查表”。

```ts
// src/core/world/biomes.ts
export interface RegionDef extends BiomeDef {
  /** 强度档（缺省 calm） */
  intensity?: 'calm' | 'scenic' | 'highlight';
  /** 邻居要有差别：调色、地貌、植被三个“家族”，相邻区域至少两个不同 */
  family?: { palette: string; land: string; flora: string };
  /** 气候带，发牌时避免沙漠紧挨雪山：temperate | dry | cold | warm */
  climate?: 'temperate' | 'dry' | 'cold' | 'warm';
  /** 海边的区域（不连着出现）、超现实的区域（六个里最多一个） */
  sea?: boolean;
  surreal?: boolean;
  /** 发牌权重（缺省 1） */
  weight?: number;
  /** 地貌：各种截面的机会与强度；新种类见“地貌算子” */
  land?: { odds: Partial<Record<LandKind, number>>; size: Partial<LandSize> };
  /** 水：湖和河的机会、结冰、河面比路低多少 */
  water?: { lake: number; river: number; frozen: number; clear: number };
  /** 锚定地貌的配方：每个区域几处、哪几种、多大 */
  features?: readonly FeatureRecipe[];
  /** 远景形状（0 圆丘 1 尖峰 2 桌山 3 峰林 4 火山锥 …） */
  // farShape 的取值范围扩大，老的三种不变
}
```

### W1.1 发牌与导演（第 2 版世界先用现有 6 种区域跑起来）

- **区域占整段路**：一个区域 6–8 个路段（7.5–10 km，按 60–70 km/h 加上停车，约十分钟）。区域边界落在路段边界上；过渡带仍是 900 m。
- **发牌**（`src/core/world/dealer.ts`，纯函数，每章的骰子用 `hash2(章号, 盐, 种子)`，不用顺序随机数，这样以后加规则不会让后面的章全部移位）：
  - 硬规则：不重复最近三个区域；高潮之后必接舒缓；高潮之间至少隔三个区域；前三个区域只有舒缓和有看点，第 0 个是出发地；海边区域不连着；超现实区域六个里最多一个；连着三个舒缓之后必须来一个有看点或高潮；有看点最多连两个。
  - 软规则（权重）：强度档目标占比舒缓 60 %、有看点 30 %、高潮 10 %；与上一个区域在调色、地貌、植被三个家族里至少两个不同，否则权重乘 0.15；干热与严寒相邻权重乘 0.25；很久没出现的区域权重更高，保证长途里每种都见得到。
  - 池子大小记在世界身上（`WorldOptions.regionCount`，存进存档）：以后往注册表里追加区域，不改变已经开局的世界。
- **导演**（`src/core/world/director.ts`）：只用区域数据和哈希，不读路线几何。给每个路段一份节目单：是否安静段（每个区域一段连着两个路段的安静路，不在区域头尾）、是否放锚定地貌、（以后）奇观与关口。水和地貌截面仍按区域的机会掷，规则不变（湖边要平地、海岸是山坡等）。
- 第 1 版的发牌和安静段规则原样保留在 `RULES_V1` 后面。

### W1.2 地貌算子、锚定地貌、远景形状

所有算子的共同规矩：离路中线 13 m 以内不动；坡度不超过 2:1（高度场撑不住悬崖）；一阶导数连续；只用算术和哈希；不回调 `world.shape`。

- **截面算子**（`LandformPlan.offset` 里，参数跟着路段在边界上平滑过渡）：
  - 梯田 `terrace`：把山坡的剖面重映射成一级一级的平台（每级 3–5 m，平台占四分之三，田坎占四分之一，沿等高线带一点弯）。强度 0…1 可以平滑过渡到没有梯田。
  - 沙丘 `dune`：16 m 以外叠加不对称的脊状起伏（迎风面缓、背风面陡，沿风向拉长），4–10 m 高。
- **锚定地貌**（`src/core/world/features.ts`，按路段依次生成，和湖一样有包围盒，在 `shape` 里海之后计算）：
  - 峰林 `tower`：一簇 5–14 座，离路 90–700 m，底半径 40–110 m，高不超过底半径的 1.1 倍，糖面包形；取最大值而不是相加。
  - 孤峰与桌山 `butte`：平顶，陡坡，红岩区域用。
  - 火山锥 `cone`：带火口。
  - 生成时检查：整个包围盒离路中线不小于“半径 + 30 m”；不压湖和河。
- **远景形状**：`relief()` 的远景按 `farShape` 分发，新增 3 峰林（小格子的陡峰）、4 火山锥群。老的三种不变。
- **代价**：`shape` 每次调用新增不超过 0.3 微秒（Node 实测并写明）。

- 新区域 6 种，把上面的算子和三档强度里的前两档都用到，并且和“长什么、采什么、吃什么”关系最大：

| 区域 | 强度 | 地形从哪来 | 植被与物产（W2、W3 做） |
| --- | --- | --- | --- |
| 花海原野 `flower_fields` | 舒缓 | 很缓的起伏（草原家族，近景起伏减半） | 成垄的花、蜂箱 |
| 梯田山乡 `terraces` | 舒缓 | 山坡加梯田算子 | 稻、茶、辣椒、紫苏 |
| 湿地沼泽 `wetland` | 舒缓 | 平，湖多 | 芦苇、蔓越莓、水芹 |
| 竹海 `bamboo_sea` | 有看点 | 森林家族的谷与坡 | 竹、笋、茶 |
| 红岩峡谷 `red_canyon` | 有看点 | 峡谷截面、近处的桌山、孤峰 | 鼠尾草、仙人掌果 |
| 喀斯特峰林 `karst_peaks` | 有看点 | 平谷底、峰林、远景峰林 | 花椒、野山药、茶 |

- 每种区域一个文件（`src/core/world/regions/<id>.ts`），外加渲染层一份调色（`src/game/scene/palette.ts` 的表）。植被在 W2 之前先沿用 `kin` 的。
- 高潮档的区域（冰川垭口、超现实区域）需要回头弯、关口和大模型，留给 W4；发牌规则已经为它们留好位置，现在没有高潮区域时按剩下两档归一。
- 游戏：新开一局用第 2 版；存档记 `world: { seed, version, regionCount, rev }`；`rev` 是生成器修订号，读到修订号不同的存档时把车和人放回路上同一里程处、散落的东西落到地面，其余照旧（开发期间第 2 版的输出还会变，这样老的第 2 版存档不会把车埋进山里）。
- 测试面板“传送”页签：传送到任一种区域；“旅程”预览：导演排出的前 60 个区域和强度曲线。

## 怎么加一种区域（给以后的会话或更便宜的模型）

1. 在 `src/core/v3/contracts/regions.ts` 里确认它的 id、名字、强度档。
2. 新建 `src/core/world/regions/<id>.ts`：填 `RegionDef`（路的风格、近景与远景起伏、地貌机会与强度、水、锚定地貌配方、家族、气候），在 `src/core/world/regions/index.ts` 的列表末尾加一行（只能加在末尾）。
3. 在 `src/game/scene/palette.ts` 的表里加它的调色。
4. 在 W2 的植物表、W3 的采集表里给它加行（表以区域 id 为键）。
5. 跑 `npx vitest run harness/sim/world_*.test.ts harness/sim/v3_world*.test.ts`：金样（老世界不变）、发牌规则、坡度与台阶门禁都要过；用测试面板传送过去看一眼。
6. `REGION_COUNT` 加一，生成器修订号加一。
