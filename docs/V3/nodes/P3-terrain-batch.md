# 地面分批画、每帧只算一次矩阵

2026-11-20。湖区的绘制次数还超预算（437 次，预算 400）。逐项数下来，单项最多的是地面：每块地面一次，屏幕上 79 次。

## 地面分批画

地面是一棵四叉树，叶子从 256 米到几十公里一块。每片叶子都是同样的网格：33×33 个点，四边各加一圈裙边，共用一套三角形索引（`scene/worldBuild.ts` 的 `buildTerrain`）。

- 用同一种材质画的叶子，合进几个"批"（`scene/terrainBatch.ts`）：
  - 一批 64 个格位；远处那圈叶子各带自己几段的调色，每种调色一批，16 个格位。
  - 一片叶子进来：占一个空格位，把它的点抄进去，用它自己的位置画在那里。
  - 一片叶子走了：格位藏起来，留给下一片。叶子都一样大，所以一批的缓冲区不会越用越大。
  - 一批画一次（WebGL 的一次多重绘制），每片叶子仍按自己的包围球裁剪。
- 远处那圈的调色批，随它最后一片叶子一起释放。
- 视点原点挪动时，每片叶子按世界坐标重新放好（`rebase`）。
- 着色器（`render/terrainMaterials.ts`）多读一个"这片叶子在哪"的矩阵，其余不变。

画出来的地面和原来一样：湖区驾驶位截图前后肉眼看不出差别（`loop/shots/perf_gate/lakesnow_lakes.png` 对比 `tb1_lakes.png`）。

## CPU 每帧在忙什么

借这次把渲染一帧的 CPU 时间剖析了一遍（湖区，只计 `render()`，帧与帧隔开，不读回）：

| 项 | 每帧毫秒 | 做了什么 |
|---|---|---|
| 整个场景的矩阵更新 | 1.65 → 0.79 | 两张阴影图、植物阴影、屏幕，一帧画四遍场景，渲染器每遍都把全部矩阵重算一次。现在一帧开头算一次（`render/core.ts`），四遍共用 |
| 调色和室内光的数组 | 0.70 → 0.03 | 几十个颜色数组几乎每个材质都读。three.js 遇到"向量数组"，每次切换材质都要一个个拷成平的数组再上传；改成直接存平的数组（`render/uniformArrays.ts`），GPU 拿到的数一样 |
| 地面的绘制 | 79 次 → 12 次 | 见上 |

- 合计：湖区渲染一帧的 CPU 时间从 6.2 毫秒降到 4.4 毫秒（剖析器下量的，它本身也占一点）。性能检查里不开剖析器时，五处是 1.9–3.2 毫秒。
- 室内光改了存法，车库里开灯的截图前后逐像素比过：不同的只是排气的烟、飘字的淡出、风吹的草这些随时间动的东西。

## 性能检查脚本的两处改动

`harness/shots/perf_gate.mjs`：

- 多量一个"CPU 部分"：只量 `render()`，一帧一次，不读回，所以 GPU 那边排队不算进来。另一个程序占着显卡时，带读回的帧时会乱跳，这个数不会。
- 计时前先等树的远处照片烘完。远处照片一帧最多烘一张，每张约 11 毫秒；以前计时的那几十帧里常有几帧在烘，帧时和 P95 都被拉高。现在先画到没有要烘的，再计时，并打印用了几帧。
- `BatchedMesh` 按它裁剪后实际画的块计三角形和绘制次数。

## 结果

| 地点 | 地面的绘制次数 | 总绘制次数（含阴影） | 预算 400 |
|---|---|---|---|
| 森林 | 115 → 42（含路） | 324 → 251 | 达标 |
| 草原 | 118 → 50 | 376 → 308 | 达标 |
| 雪山 | 99 → 25 | 288 → 214 | 达标 |
| 雪山远眺 | 131 → 51 | 307 → 227 | 达标 |
| 湖区 | 118 → 52 | 437 → 371 | 达标 |

- 五处的绘制次数第一次全部在预算内。
- 实际开 3 公里（`p0_drive_live.mjs`）：12,065 帧，平均 11.6 毫秒，P99 21.3 毫秒，最长 41 毫秒，没有超过 50 毫秒的卡顿。
- 帧时（带 GPU）这次不作数：另一个会话的 Nomad Drive 一直开着，显卡空闲时也有 68 % 被它占着，同一处前后几次相差 4–8 毫秒。

## 还超的

- 草和花的三角形：五处 1.24–1.42 百万（预算 1.2 百万）。是 M5 的占位地被植物，阶段 3 换成工具箱的地被。
- 湖区的车辆三角形 0.32 百万（预算 0.3 百万）：那里停着 4 辆车。
- 树的远处照片在主线程里烘，每张约 11 毫秒：开车时每遇到一种新树就有一帧变长。下一步挪到后台线程。
- 路面还是一段一次（28 次）。不同远近的路段点数不一样，要合批得按档分格位，放到后面。

## 验证

- 类型检查、生产构建通过。全部单元测试：2,259 项通过，1 项是已知的计时测试（`v3_world_gen` 的地形函数耗时），满负荷时偶尔超，单独跑 27 项全过。新增 `harness/sim/p3_terrain_batch.test.ts`：格位占满开新批、空出的格位给下一片、调色批随最后一片释放、原点挪动后重新放好。
- 冒烟：`modcar_journey`、`modcar_save`、`modcar_workshop` 通过。

## 以后加东西

另一种"每块网格一样大"的东西（比如以后的地块装饰）也可以用 `TerrainBatch`：构造时给每块的点数和索引数，`add(geometry, material, wx, wy, wz, keep)` 放进去，`remove(slot)` 拿走，原点挪动时调 `rebase()`。材质的顶点着色器要加 `#include <batching_pars_vertex>`，在 `USE_BATCHING` 下乘上 `getBatchingMatrix(getIndirectIndex(gl_DrawID))`。

新的着色器数组一律用 `vec3s(n)` / `vec4s(n)` 存平的，写用 `put3` / `put4`。
