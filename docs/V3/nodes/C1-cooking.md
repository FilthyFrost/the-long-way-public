# C1 烹饪：设计（规则与数值）

状态：设计（2026-11-19，主会话；W1–W3 接线期间先写规则与数值，W3 打标签后开工）。玩法说明在 `docs/V3/PLAN.md` 的“烹饪”一节，菜的分类在 `docs/V3/CATALOG.md`；验收条件在 `docs/V3/STATUS.md` 的 C1 一节。这里定的是底层：食材怎么描述、下锅怎么出菜、一道菜值多少、增益怎么算。

## 和现有数值的关系

身体的规则在 `src/core/modcar/vitals.ts`：饱食 100 点能撑 48 分钟；一罐鲭鱼 75 点，一袋虾片 20 点。采集物生吃一份 3–12 点（`src/core/v3/forage/kinds.ts`）。烹饪要让“摘来的东西做成一顿饭”明显划算，又不压过罐头太多：

- 四份采集物生吃约 12–25 点；做成一道菜约 30–45 点，再加一个增益。大约是生吃的 2.5 倍。
- 肉和鱼（狩猎、钓鱼落地后）一份生的 10–18 点、生吃会闹肚子；做熟的一道主菜 50–75 点。
- 罐头和冷冻食品也是食材（按标签归类），做成菜比直接吃多三成，并且能带上增益。

## 食材

每种能下锅的物品有一行“食材特性”（`src/core/v3/cooking/ingredients.ts`）：

| 字段 | 含义 |
| --- | --- |
| `cls` | 大类：肉、禽、鱼、贝、蛋、菌、菜、根茎、果、谷、坚果、香草、香料、花、甜、奶、水 |
| `food` | 一份的基础饱食点数（取物品自己的生吃点数；不能生吃的另给） |
| `taste` | 五味的贡献：咸、甜、酸、辣、鲜，各 0–3 |
| `tags` | 物品自己的标签（`forage`、`meat`、`fish`、`salty`、`tea`…），菜谱按标签点名 |
| `raw` | 生吃是否安全（肉和鱼不安全） |

采集物的 80 种由数据表按类别自动得出，逐种可以覆盖；现有的 106 种物品里能吃的（罐头、冷冻食品、饮料）各给一行。鱼和肉在各自的节点注册物品时带上同样的字段，菜谱不用改。

品质（物品的 `q`，1–5 星）和新鲜度（新鲜、还行、快坏了）跟着每一份食材进锅：快坏了的食材拉低星级，坏了的不能下锅。

## 做法与器具

做法由用的器具决定，一共 11 种：

| 做法 | 器具 | 倍率 | 另外 |
| --- | --- | --- | --- |
| 拌 | 碗 | 1.2 | 不用火 |
| 烤 | 烤叉（篝火）、烤网 | 1.6 | 篝火就能做 |
| 煎 | 平底锅 | 1.7 | |
| 炒 | 炒锅 | 1.7 | |
| 蒸 | 蒸笼 | 1.7 | |
| 煮汤 | 汤锅 | 1.8 | 水分 +15 |
| 炖 | 汤锅、荷兰锅 | 2.0 | 水分 +8，要等 |
| 饭面 | 汤锅加谷物 | 2.0 | |
| 烘焙 | 烤箱、荷兰锅 | 1.9 | 要等 |
| 饮品 | 水壶 | 1.0 | 水分 +25 至 +35 |
| 存：晾干、烟熏、腌、发酵 | 晾架、熏箱、坛子 | 1.3 | 不是一顿饭，是把保鲜期拉长 10 倍到不限；发酵随里程成熟 |

火源三档：篝火（只能烤和烧水）、便携灶（单头：煎、炒、煮、蒸）、房车厨房（全部）。T1 之前房车里的厨房是固定位置。

## 一锅出什么（规则引擎，`src/core/v3/cooking/rules.ts`）

输入：做法、1–5 份食材（每份带种类、品质、新鲜度）、各工序的完成度（0–1）。输出：哪道菜、几份、每份的饱食、水分、生命、增益与时长、星级。纯函数；同样的输入永远同样的输出。

1. **先认菜谱。** 菜谱是一行数据：做法、必需的槽（“任意菌 ×2”“#鱼 ×1”“野葱”这样的标签或具体种类）、可选的配料、味型目标。一锅东西满足某道菜谱的全部必需槽、并且没有它不容许的东西，就是这道菜；同时满足多道时取最具体的那道。所以随便下锅碰巧放对了，就“悟出”这道菜谱。
2. **不是菜谱就按类别出菜，永远有结果。** 主料（点数最多的大类）加做法得出通用菜名（“蘑菇汤”“烤串”“野菜沙拉”“杂粮饭”）；大类之间有一张相容表（甜的和鲜的冲突，香草和香料百搭），相容度低就是“说不清的一锅”：能吃，点数打八折，没有增益。
3. **份数。** 三份食材以内出一份，四到五份出两份。
4. **一份的饱食** = 食材点数之和 × 做法倍率 × 星级系数（0.8 + 0.1 × 星级）÷ 份数，菜谱菜再加 10。上限 90。
5. **星级 1–5** = 食材品质 35 % + 火候 25 % + 调味 20 % + 刀工 10 % + 这道菜做过的次数 10 %（3、8、15 次各进一档）。自由下锅没有调味和刀工，最高三星；快坏了的食材每份扣半档。
6. **增益**：菜谱菜有它自己的增益；通用菜按主料和香料给一个常见的（见下表），相容度低的没有。时长 = 基础时长 ×（0.7 + 0.15 × 星级）。

## 增益（接到身体数值的通用限时增益）

身体现在只有固定的几种效果。C1 先在 `vitals` 旁边开一个通用的限时增益表（任何系统可以注册增益、查询强度），再把下面十种接上去。同一时间最多两个“饭”的增益加一个“饮品”的增益；再吃一顿，顶掉最早的那个。时长是现实时间，基础 5–12 分钟。

| 增益 | 作用 | 现在就生效 / 等谁 |
| --- | --- | --- |
| 暖身 | 体温向上的拉力 | 现在 |
| 清凉 | 抗热 | 现在 |
| 有劲 | 体力回复加快 30 % | 现在 |
| 耐饿 | 饱食消耗减 25 % | 现在 |
| 解渴 | 水分消耗减 25 % | 现在 |
| 负重 | 大件搬得更快 | 现在 |
| 眼尖 | 采集微光提示更远、足迹更清楚 | W3 现在，足迹等狩猎 |
| 手稳 | 瞄准晃动小、钓鱼时机窗口宽 | 钓鱼、狩猎 |
| 脚步轻 | 动物更晚发觉 | 狩猎 |
| 好运 | 双倍产出的机会 +10 % | W3 现在，掉落等工作台与蓝图 |

## 150 道菜谱怎么排

12 类的数量按目录。第一版先写满不依赖鱼和猎物的那一半（菌、菜、根茎、谷、果、蛋、罐头：汤、炒、烤、蒸、饭面、凉拌、甜点、饮品、野营简餐里大约 75 道），其余按标签写好（“#鱼”“#红肉”“#禽”“#贝”），食材落地时自动能做；测试面板可以调出占位食材验证。每种区域 4–6 道招牌菜，用当地的采集物。

## 工序（界面与手感，由实现的人按 `PLAN.md` 的表做）

切、下锅、火候、调味、等、装盘，每道菜 2–4 个，每个 3–10 秒；完成度 0–1 进上面的星级公式。“自动调味”开关给不想调味的人，按 0.7 计。机器人厨子按固定完成度走一遍，用来测时长（60–180 秒）和星级分布。

## 保鲜三档与发酵

- 物品模型里已有：容器的 `holds.decay` 让里面的东西坏得慢（篮子 0.5；冷藏箱 0.25；冰箱 0.1）。C1 加冷藏箱和冰箱两件家具或物品。
- 晾干、烟熏、盐腌把食材变成另一种物品（“蘑菇干”“熏鱼”“咸菜”），保鲜期 10 倍到不限，仍然是食材。
- 发酵坛：放进去的东西按行驶里程成熟（每 5–10 km 一档），到下一个区域正好能吃。

## 分工

1. 主会话：`ingredients.ts`、`rules.ts`、`recipes.ts`（先 75 道）、通用增益表的核心，和它们的测试（规则穷举、每道菜的食材都拿得到、数值在区间内）。
2. 一位工程师：游戏模块（器具物品与摆放、火源、把东西放进锅、工序界面、出菜与吃、增益接到身体、发酵与保鲜、测试面板、机器人厨子、实机脚本）。
3. 一位工程师（可并行）：器具与菜的模型、锅里的样子（颜色、蒸汽、火候的五档）、图标；自检截图。

## 怎么加一道菜

在 `recipes.ts` 末尾加一行：类别、做法、必需的槽、可选配料、味型目标、增益；跑 `npx vitest run harness/sim/v3_cooking*.test.ts`（它会检查这道菜的食材拿得到、不会被更具体的菜谱永远盖住、数值在区间内）。
