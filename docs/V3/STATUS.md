## 执行方式（用户 2026-11-19 00:07 更新，以此为准）

- **先做世界根基，再往上做玩法。** 第一优先是新的随机地形与地貌生成、与地形绑定的植被、可采集的植物（野菜、水果等）以及真正的生成与采集机制：世界里长什么、在哪里长、能采到什么，要做完整。最重要的底层算法、数值、随机生成机制和它们之间的关系先做扎实，不留到后面。
- 根基之后先做完整的烹饪，再做钓鱼（鱼竿、鱼饵、各种鱼），其余按同样的依赖与重要性排。
- 目的：即使额度后来不够，也已经留下最关键、可靠、能运行的基础和完整成果；次要的后续内容以后可能交给更便宜的模型，所以每个节点都要留下“怎么加一行内容”的说明。现在不换模型。
- Ultracode 已关闭：不再默认编排多代理工作流。主会话自己做设计和核心算法的第一版；只有确实能省时间、文件不重叠的部分才交给少量子代理，高风险的合并（存档、世界确定性）才安排独立审查。最高思考等级。注意额度。
- 模型（2026-11-19 更新）：Fable 5.2 的额度在 W2、W3 进行中用完（2026-11-20 08:00 美国太平洋时间重置）。用户把会话切到 Opus 5.5、最高思考等级，要求从现有进度接着做、不重做不丢弃。新开的子任务一律指定当前模型（Opus 5.5）；不再唤回在 Fable 上开的子代理，改为新开 Opus 子代理在原分支上接着做。提交署名随之改为 Opus 5.5。
- 仍然逐步交付：每个节点做到可玩、可验证、集成通过，本地提交并打标签，更新本文件，向用户汇报；不等用户审阅。
- 只动本工程；只做本地提交，不推送，不对外发布；不买额度。美术与质量目标不变。这台开发机没有独显，任何截图和时间都不是显卡实测。
